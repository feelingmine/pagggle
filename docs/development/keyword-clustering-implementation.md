# 两阶段关键词聚类实现与验证

依据：用户指定的 `hybrid_seo_keywords_clustering_engine.md`。原设计文档与 PRD 不改写。网站输入/sitemap/正文解析功能仍为待用户验证；用户本轮明确授权开始独立关键词聚类实现。

## 交付范围

CSV/XLSX/逐行关键词 → 预览及导入对账 → 本地 all-MiniLM-L6-v2 原词向量 → AgglomerativeClustering（cosine、average）→ 同语义组内对证据充分的词进行 SERP 并集匹配（默认至少 3 个相同 URL），证据不足的词保留语义分组 → 按搜索量降序、KD 升序建议一个主词，其余为次词。

代码初始距离阈值默认 0.65；2026-10-09 使用用户固定的 4,869 条真实关键词发现该阈值会形成 4,637 词的大组，本机 `config.json` 调整为 0.30。此值是本批数据的初步校验值，不是已完成普适校准的参数；未修改其它设置或产品 PRD。

文档示例测试使用其执行示例阈值 2；产品默认仍为 3。阈值只是初始实验值，尚未由真实业务标注集校准。没有创建正式 PagePlan 或 URL，没有自动查询搜索服务，没有自动重跑站点理解。

与 PRD 的关系：本轮为用户指定的原词单路两阶段引擎，属于候选发现实现。意图双路向量、大模型逐成员同页审核、人工 must_link/cannot_link、拆合谱系及增量正式问题组尚未实现，不能把此引擎宣称为 FR05 全部验收完成。

## 参考代码修正与边界

- 修正 RoleAnchor 将全体成员标为 Primary 的错误；每组恰好一个主词。
- 缺失搜索量/KD 保留 null。未知指标排在已知值之后，存在缺失时标为暂定排序；不填零。
- SERP 缺失、条数不足或上下文不完整的词，在各语义主题和相同上下文内保留为 `semantic_only` 分组，标为 needs_evidence / 同页关系待验证；空集合不能证明词应单独建页。这些词不参与 URL 比较、不伪造两两搜索证据，也不作为桥梁并入证据充分的组。不同市场、语言、来源、日期、设备分开比较。
- 对证据充分的词保留设计文档的并集匹配（`serp_overlap`），附加全组成员对覆盖检查，链式关联明确标为 needs_review。所有输出都只是候选；URL 重合不是搜索引擎已确认同一意图的证明。
- 排序与基于成员 ID 的候选编号保证同输入重复运行稳定。每次结果独立留档，不覆盖历史；新输入会提示未纳入旧版本。尚未实现增量重分组或发布映射。
- 完整 URL 比较：规范化域名大小写、默认端口和 fragment；保留路径、查询参数、协议差异，不将同域名的不同页面合并。不访问导入的 SERP URL。
- 每词最多导入前 10 条去重自然结果 URL，超出报错而非截断；支持换行、逗号或 JSON URL 数组。SERP Features 不是结果 URL。
- CSV 支持标准列及文档的 Semrush 列名；XLSX 仅单工作表，拒绝公式。按用户后续要求，导入不设行数、列数或总文件大小的固定上限；额外列保留原始值，失败、重复记录仍留存，跨项目去重互不影响。
- `clustering_*` 参数集中在根 config.json；config.example.json 无凭据。模型文件在忽略的 data/models，脚本只下载公共模型；运行时 local_files_only，关键词仅在本地编码。模型令牌超长时明确拒绝，不默认截断。
- SERP 随导入记录保存在项目范围中，日期/来源不同的快照不相互覆盖。没有计费 SERP API 或跨客户缓存。
- 层次聚类和组内覆盖检查最坏仍有平方复杂度；未宣称文档的 O(N) 或固定 99% 提速，尚未做万词性能验收。

1. 算法与导入：16 项定向测试通过。覆盖真实 sklearn 分区、SERP 拆分、唯一主词、未知指标、链式重合、输入顺序稳定性、缺失/异上下文快照、CSV/XLSX 等价、日期参与去重、公式/表头异常、取消与无效向量。
