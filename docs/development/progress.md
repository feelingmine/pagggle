## 第四步：环境恢复与真实站点采集

用户提供试点网站并报告解析失败。实际诊断发现两层问题：系统 DNS 将公网域名映射到代理 Fake-IP（198.18.0.0/15）；获得真实公网地址后，本机 HTTP 请求仍收到 202 验证码中转页。

修复与验证：

1. 新增 `crawl_dns`（system/cloudflare），加密 DNS 的结果仍做公网校验；直接连接仍固定已校验 IP，避免重新解析。私网、测试网及解析异常有自动化覆盖。
2. 新增 `crawl_backend`（direct/firecrawl）、独立 SecretStr 采集凭据和单页时限；按 Firecrawl 官方 Scrape API 读取原始内容。先核对 robots，再进行同站有界采集。配置仅存本地 config.json，已有 CLI 凭据安全复制后不输出其值。
3. 验证码/中转 HTML、非 200 响应、返回不同域名均拒绝作为正文保存。失败记录仍保留，成功读取的快照不被重试覆盖。
4. 在用户已创建的原项目重试：20 个 HTML 页面和 4 个发现资料读取成功，90 个链接因页面上限标为未覆盖。实际网址、正文、模型产物仅在忽略的 data/ 中，不复制进工程文档。
5. 真实模型提取曾出现 finish_reason=length、6000 输出 token 用尽且正文为空。依据 DeepSeek 文档增加可选 model_thinking，并为本地提取配置 disabled、model_max_tokens=12000。不是换模型，也未自动接受损坏 JSON。
6. 真实画像 v1 成功生成并通过精确引用校验，仍为草稿等待用户核对。20 份来源在模型输入预算内均有截取，不能将模型未见信息等同于整站没有该信息。加入当前分析日期和截取范围提示；不合格新引用仍拒绝写入、原版本保留。

资料隔离：正常服务使用原项目库；HTTP 点击流及意图调用使用 data/verification/http.sqlite3 的明确合成项目。网页请求 /config.json、/data/pagggle.sqlite3 均为 404；配置文件权限 0600，代码与文档密钥扫描通过。

局限：Firecrawl 使用外部采集额度，远端抓取由服务方执行，本机不能像 direct 模式一样为其固定连接 IP。当前未实现采集费用完整对账、站点任意动态交互、单页重试入口或完整覆盖验收。
