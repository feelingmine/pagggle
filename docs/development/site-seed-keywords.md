# 网站分析搜索基础词实现与验证（2026-10-09）

产品范围见 [补充需求](../product/网站分析搜索基础词补充需求.md)。本功能衔接网站业务理解与外部关键词工具拓词，不自动抓取新页面、不重做业务理解、不导入或聚类这些基础词。

## 实现

- “业务理解”增加“搜索基础词”章节、提取入口、产品/服务分类、中文类别说明及网站语言的关键词。单词可点击复制，全部复制为逐行词表；每项可以查看支持主张、原文与原始页面资料。无法写入剪贴板时提供手动复制框。
- `POST /api/projects/{id}/jobs` 增加 `seed_keywords` 类型，要求当前 `profile_version`。复用现有任务互斥、取消、失败与页面轮询；重试返回业务理解页面。
- 从当前业务理解中选取 confirmed/stated 的 product/business/capability 主张，排除未确认、推断和冲突项。实际模型输入只包含这些主张所引用的同站、已读、page 类型来源的原文、URL、分类和索引；人工陈述、修订说明、手工补充资料、其它站点来源、关键词表及凭据不进入模型上下文。
- 模型沿用根 config.json 配置，没有新增配置项或更换模型、密钥。输入超出预算会报错，不截断；无可用来源、网络错误、输出耗尽或格式不合格保留已有结果。
- Schema 和程序校验类别枚举、词条格式、重复词及主张索引；并列词表不能伪装成单个基础词。校验失败最多自动修正一次，仍失败则不保存部分结果；两次成功请求的 token 使用量累计记录，费用未知。行业类别是否准确仍需业务核对，程序校验不等于人工语义审核。
- 数据库 v6 → v7 新增 `seed_keyword_runs`，按项目、任务与业务理解版本保存独立结果，旧记录不覆盖。保存时再次检查运行状态、任务归属及最新画像版本；结果、模型用量和事件在同一事务内写入。历史画像只显示绑定该版本的基础词，刷新不自动提取。

## 实际验证

固定网站 siliconeproductsmanufacturer.com，原业务理解 v28，共 15 条可用主张依据，全部来自该站已保存页面。初次输出存在并列类别及流程词问题，后续补充原子类别约束和一次修正规则；保留初版结果与失败记录供追溯，没有手工伪造模型结果或修改网站数据。

最终保存 14 个基础词：11 个产品类、3 个服务类。杯与瓶已分别归为独立搜索词，服务词归纳为定制制造、模具开发和 ODM 产品开发。每个词的索引都属于该版本支持的主张，引用对应已有原文；不填搜索量和 KD，未把未读取页面当作已覆盖。结果来源范围是已有业务理解，不宣称重新完成整站分析。

验证顺序：

1. 既有后端 98 项和前端 5 项回归通过，确认无活动任务并通过 SQLite backup API 备份后迁移本地库。
2. Chrome 从页面发起真实提取。第一次工具自动审批拦截了可能包含人工私有内容的模型输入；随后核验引用均属于用户指定网站，并从代码中去除人工描述等字段，收紧为网页引用后获准执行。没有经其它路径绕过拒绝。
3. 专项 6 项通过：使用真实项目数据库副本和实际保存的模型输出回放，验证公开上下文、依据校验、接口版本冲突/项目不存在、数据不变、取消不落库、互斥及最多一次质量修正。没有构造合成业务项目或替换输入内容，测试副本保存在忽略的 data/verification/seed-tests。
4. 最终后端常规回归 98 passed、私有数据用例默认跳过 7 项（1 项聚类和 6 项基础词），既有依赖提示 2 条；前端 5 passed，语法及 diff 检查通过。基础词专项通过显式开关独立执行。
5. Chrome 显示 14 词的产品/服务分栏；“复制全部”显示成功提示，依据弹窗可进入已有原始页面资料。390px 页面宽度与 viewport 一致，14 个词条均无横向溢出；保留桌面白底橙色样式。未读取系统剪贴板，复制校验以点击执行及成功提示为依据；未强制模拟浏览器拒绝剪贴板权限。
6. 网站来源、全部 28 个业务理解版本、4,869 条原始关键词、导入批次、意图、两版聚类及首次筛选状态，迁移/提取前后逐表哈希一致；原 XLSX 的 SHA-256 不变。仅新增基础词任务、结果、用量及事件记录。

复验：`PAGGGLE_VERIFY_FIXED_DATA=1 PYTHONPATH=backend .venv/bin/pytest backend/tests/test_fixed_seed_keywords.py -q --basetemp=data/verification/seed-tests`。该命令回放已有真实结果，不再次请求线上模型；需本地固定网站及历史提取记录，缺少时不能用虚构数据代替。备份、上下文核验和结果摘要继续保存在忽略的 data/ 目录。

## 基础词编辑（2026-10-09）

新增逐词编辑弹窗，可改关键词、分类说明和产品/服务类型。`POST /api/projects/{id}/seed-keywords/{run_id}/terms/{index}` 接收三个可编辑字段及 expected_revision；不允许客户端修改来源索引。保存事务检查项目/词表归属、当前画像和提取版本、任务互斥、修订号以及重复词，内容相同返回未变化。

v8 新增 seed_keyword_revisions，全词表快照追加保存，原 seed_keyword_runs 不改写。项目快照返回当前有效词表、原提取词表和修订号。人工编辑词显示标记，依据弹窗明确引用仅作原提取参考；复制使用当前有效值。重新提取已有人工修订的词表需要点击确认，旧词表可通过提取版本下拉查看和复制；历史版本只读。

专项扩展为 9 项，通过真实数据副本验证持久化、未改变内容不写入、过期修订/旧画像/旧提取结果拒绝、重复及空词拒绝、项目隔离、来源字段保护及重新提取后人工修订保留。保存测试只对原词改变字母大小写，不创造业务词，线上项目没有被这些测试修改。既有后端 98 项及前端 5 项回归通过。

Chrome 原项目检查弹窗三个字段及当前 14 项的编辑入口，原值不变保存成功并关闭弹窗；未增修订。迁移与页面验证前后原网站、画像、关键词、聚类、提取词表、任务及用量逐表哈希一致。未触发重新采集、分析或模型请求。备份和核验基线位于忽略的 data/backups 和 data/verification/before-seed-editing.json。
