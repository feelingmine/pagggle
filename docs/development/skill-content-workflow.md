# 内容规划的 skill 执行改造

## 问题与范围

旧 content_strategy.py 把硅胶行业对象、客户任务和建议模板固化在代码中，无法作为换一轮关键词后继续使用的策略分析。它只保留用于旧版本的历史重放。新运行必须实际加载配置中的 content-strategy / seo-audit SKILL.md，调用已配置模型，并保存指令、输入、输出、使用量与校验记录。配置和客户资料仍不进入 Git。

## 固定流程，动态语义

1. 冻结关键词、基础词、项目业务理解和已保存网站正文。
2. 对完整产品/文章/业务正文分批生成可定位的语义目录；索引/附件保留采集范围记录，不充当正文主页面。
3. 使用 content-strategy 根据当次资料提出暂定内容支柱和主题；全量关键词逐批交给模型归类，允许补充主题，不匹配词逐条保留原因。批量大小只是请求分片，不限制处理总量。
4. 合并语义重复主题，根据完整网页语义目录选择已有承接页；使用目标原文及竞品证据生成覆盖检查、价值依据和建议/大纲。没有排名、询盘、资源数据的指标保持未知，模型判断标为推断。
5. 每词恰好进入一个主题或待核对清单；引用必须精确出现在本项目已读原文。保存整个执行快照，离线重放不再次调用模型。重新调用模型可能变化，因此只承诺流程、输入和执行记录可追踪、快照可重放。

旧分析不覆盖，不修改用户关键词、已核对画像或人工修订。浏览器明确区分历史规则结果与真实 skill 执行结果，并提供调用记录。新增候选仍需要业务和 SERP 审核。

## 运行记录与校验

- 配置沿用 config.json 的 DeepSeek 服务；用户在本轮明确确认发送并执行。strategy_skill_files 指向实际本地 skill 文件，调用时完整加载，记录名称、版本和 SHA-256。无需把 skill 手工改写成行业词典。
- content_skill_calls 按 project_id / run_id 保存请求（不含 Authorization）、原始响应、校验后的输出及 token 使用量。仅同项目、同服务端点指纹、同模型和同请求可复用成功记录。失败不能静默转成规则结果。
- 网页引用允许定位模型引用中的排版空白及大小写差异，输出保存的是原文准确片段；不接受改写、增删词句。模型把菜单、页脚或同义词误当证据的语义风险仍需审核。
- 逐词归类保留模型实际给出的主题定义，目录 ID 只是提示，不能覆盖新含义。对遗漏或重复归属只重试涉及的记录；四轮后仍无唯一归属的词明确列待核对。最终每个关键词恰好进入一个主题或待核对清单。
- 旧规则结果、画像、来源、手工编辑和导入记录保留。新增表为 schema v10；界面区分历史规则、新运行和真实完成的 skill 分析，并可导出模型请求与响应。

## 并发与提前分片

- `strategy_concurrency`：每个内容规划任务的最大工作线程数，默认 10，可在根目录 config.json 设为 1–64。本地本轮已设为 10，重启服务生效。正文阅读、逐词归类、主题审核的独立任务同时提交；有前后依赖的阶段仍顺序执行。索引/网站采集的并发仍由原采集配置管理。
- 完成进度按实际完成顺序更新，结果仍按输入顺序汇总；失败或取消会停止尚未执行的排队任务。已经在途的 HTTP 请求不能强制撤回，可能等待响应或超时后退出。
- 输入预算 `model_input_chars` 计量序列化后的业务 JSON（包含转义、标题和上下文），不是模型完整上下文 token 上限；skill/schema 系统指令额外占用上下文。正文在请求前分段，优先换行边界，所有字符保留。元数据本身超过预算时明确报错，不能靠截断资料继续。
- 关键词每批上限同时受 `strategy_keyword_batch_size`、输入预算和预估输出预算约束。输出估算保留 1,024 tokens，再按每词 80 tokens 预留结构/主题开销；它不是精确 tokenizer，仍保留异常输出后的递归分片与完整性检查。正文摘要的单批条数也受输出预算约束。
- 超长目标页先分段审核，再分批汇总检查项和原文引用，不能把某段未见误当整页缺失。每段实际调用与合并结果均保留。若结构化汇总本身无法放入预算则明确失败，不丢弃内容。主题合并已改为编号响应和目录分片逐轮对齐；全站页面语义目录及不含正文的业务上下文仍受单次输入预算约束，不宣称任意规模可无限扩展。
- 当前真实输入的本地预检：56,457 词 → 413 批，每批最多 137 词；最大业务输入 32,733 字符。211 个已读正文页（本站 205 + 竞品 6）→ 84 个阅读批次。分片前后无关键词或正文丢失；这些是请求计划，不是完成的模型分析结果。
