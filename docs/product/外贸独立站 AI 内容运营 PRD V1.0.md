**版本：V1.0　基线日期：2026年10月8日　状态：需求基线已固化**

本 PRD 定义面向已上线外贸独立站的 AI 内容运营产品。系统从理解已有网站的业务、产品、能力、案例、客户和内容基调开始，将搜索关键词及其他客户问题转化为可评估、可排序、可交付的页面任务，持续完成产品相关页面与 Blog 的建设和更新，以获得有效询盘为业务目标。

本版本固化需求范围、流程、核心数据对象、算法路线和验收规则。算法阈值、具体模型、数据供应商及首个发布平台属于实施配置，需在试点中确定；不代表产品已经开发或增长效果已经验证。

来源：[外贸独立站内容运营需求与实施方案](https://chatgpt.com/space/page_195adf884a9c8191a05310419c7f3da8)。后续范围变更形成新版本并记录影响，不静默改写 V1.0 基线。

## 1 产品目标与成功定义

产品要帮助用户持续回答四个问题：我的网站适合覆盖什么需求；接下来最值得做哪些页面；怎样写出真实、专业且有差异的内容；怎样稳定完成审核、发布与复查。

| 目标层级 | 定义 | 判断方式 |
| - | - | - |
| 业务结果 | 更多与企业实际业务相关的有效询盘 | 实际接收后排除垃圾、重复和测试；适配度另行记录 |
| 内容决策 | 选对问题和页面，减少无效或重复建设 | 页面方向接受情况、分组和任务修订情况 |
| 内容质量 | 信息真实，能够支持采购或技术判断 | 事实依据、问题覆盖、独特信息及行动入口 |
| 运营效率 | 降低人工整理、整合稿件和审阅时间 | 与当前多模型拼稿或人工流程比较 |
| 持续交付 | 按约定节奏完成文章和产品页任务 | 周计划完成、等待原因、发布记录 |

页面数量、收录数量、AI 检测分数和模型自评分不作为最终业务目标。排名、曝光、点击是诊断指标，按钮点击不是实际询盘。

## 2 目标用户与使用场景

目标客户是已经上线独立站、拥有真实产品或服务、希望增加询盘，但无法稳定投入专业内容运营的外贸企业。首批试点需有基本业务资料、事实确认人，以及页面修改或交付对接方式。完整关键词表和历史流量不是启动前提。

| 使用角色 | 主要任务 |
| - | - |
| 经营者或运营负责人 | 确认业务理解、主推方向、周计划与页面任务 |
| 产品或技术人员 | 核对参数、用途、能力边界和案例，不必承担全文写作 |
| 内容运营或交付人员 | 检查大纲与稿件、处理发布和效果记录 |

角色可由同一人承担。V1.0 不要求先建设复杂企业审批与组织权限体系。

核心场景：从一个网站 URL 启动理解；导入一批关键词形成页面计划；补充一条客户问题启动内容任务；根据新产品资料更新现有页；每周交付至少两篇 Blog 并单独安排产品页任务；根据搜索及销售反馈调整后续计划。

## 3 用户痛点与产品原则

| 用户痛点 | 对应需求 |
| - | - |
| 网站已经上线，但无人持续运营 | 保留业务上下文，维护周计划和可恢复的任务状态 |
| 关键词多，手工分类耗时 | 大模型意图抽取与聚类形成可审核的问题组 |
| 不知道哪些词值得做 | 将业务价值、搜索机会、资料能力和成本共同用于排序 |
| AI 或写手不了解行业 | 从网站理解及企业事实开始，按任务补研究并追溯依据 |
| 多篇 AI 稿件仍需自己拼改 | 输出有方向、有证据、可预览的成稿，集中确认关键问题 |
| 一个词一页容易雷同 | 按主要客户任务决定同页承接，不按关键词数量创建 URL |
| 无法判断更新价值 | 记录内容变更、搜索表现和实际询盘反馈 |

业务原则：产品页及相关商业页面优先建设；Blog 覆盖选型、技术难点、采购问题与相关行业新闻。网站基调提供约束，但不盲目继承空话、过时信息和无依据承诺。客户可以从想法、样品、图纸或尚不完整的需求开始询盘，不强制成熟度筛选。

## 4 范围与优先级

P0 为首个完整试点必须具备的能力，可以先通过数据导入及有限人工协作完成；P1 增强自动化和效果反馈；P2 用于扩大规模。

| 级别 | 范围 | 实现边界 |
| - | - | - |
| P0 | 网站理解、事实与页面清单、内容基调 | 必须识别核心产品、实际能力和案例，不能只总结首页 |
| P0 | 关键词清理、意图抽取、候选聚类、同页审核与重点搜索验证 | 保留歧义与人工修订，不承诺自动处理所有边界 |
| P0 | 页面匹配、方向定义、机会评估和排序 | 允许导入外部指标；缺失信息明确可见 |
| P0 | 研究、详细大纲、产品页与 Blog 写作及检查 | 选定任务才投入完整研究，企业主张必须有依据 |
| P0 | 周计划、审核、版本、发布交付和基础结果记录 | 先适配一个试点 CMS；接入前可交付标准发布包 |
| P1 | 搜索数据自动同步、基于表现重新排序 | 首版先支持导入或人工登记 |
| P1 | 行业监测、资料与网页变化检测、知识增量更新 | 新事件进入同一问题与任务流程 |
| P2 | 多 CMS、多语言、多站点管理 | 少量真实站点验证后扩展 |

V1.0 不承诺无人审核自动发布、每个关键词一个页面、固定时间进入排名前列或固定询盘增长。不建设通用 SEO 全家桶、自有搜索量数据库、模型训练平台、复杂多模型投票体系和全站重建能力。

## 5 完整用户流程

用户提供网站地址后，系统展示可核对的网站画像；用户集中纠正关键误解。随后从关键词或客户问题识别意图，形成问题组，匹配现有页面，评估机会并推荐周任务。选中的任务进入研究、大纲、草稿、审核与发布；表现及新增资料回流下一轮。

| 阶段 | 主要输出 | 进入下一阶段的规则 |
| - | - | - |
| 理解已有网站 | 网站画像、页面覆盖、事实与基调 | 所处理业务范围有可追溯资料；缺口单独标记 |
| 关键词到意图 | 候选意图及歧义说明 | 每个输入关键词都有状态，无遗漏 |
| 意图到问题组 | 主要任务、成员、边界、轻量答案清单 | 经过同页检查，争议成员保留待核对 |
| 问题组到页面方向 | 页面对象、任务、判断、行动及现有 URL 匹配 | 有明确新建、更新、观察或补资料建议 |
| 机会评估 | 解释性排序与开展条件 | 选中且无关键阻塞的任务进入生产 |
| 研究与详细大纲 | 模块、要点、证据及待确认项 | 关键问题能被回答，缺资料不靠生成补足 |
| 草稿与审核 | 可预览内容、变更差异、检查结果 | 当前版本通过内容检查与审阅 |
| 发布与复查 | 交付状态、URL、版本和观察项 | 发布成功有实际记录，失败可恢复 |

关键词不是唯一入口。客户问答、产品变化和行业新闻可以直接进入候选问题，不必先生成假关键词或假搜索量。

## 6 功能需求

### FR01 网站接入与内容发现

P0。输入网站 URL；自动识别可读取的导航、分类及站点地图，优先覆盖首页、产品分类与详情、应用、定制、能力、案例、Blog 和联系页面。记录发现、成功读取、失败、未覆盖及排除的范围。按需要支持动态页面解析和用户资料补充。

验收 AC01：任一失败 URL 有明确状态；可以通过上传或文本补充继续；读取失败不能被解释为没有产品或案例。页面来源、内容摘要和抓取时间可追溯。

### FR02 网站理解与内容基调

P0 首项核心能力。抽取业务角色、核心产品、目标市场、客户场景、定制与供货边界、参数工艺、能力证明、案例及其产品关系、现有内容与询盘路径。建立版本化 SiteUnderstanding，输出业务能力画像、页面覆盖清单、内容基调与事实规则。

区分来源中明确陈述、模型推断、已确认和待确认；认证及案例保留适用范围。未知字段允许为空。用户可以修改，并保留修订依据。每份下游判断引用相关画像版本及事实。

验收 AC02：抽查核心产品、能力与案例能回到来源；存在冲突时不自动选一个作为事实；画像修订能定位受影响任务。内容基调保留准确术语、合适技术深度与品牌表达，同时指出原站问题。

### FR03 关键词和需求导入

P0。支持粘贴关键词及标准表格导入，接收可选搜索量、KD、市场、语言、数据时间与来源。统一格式并去除完全重复记录，保留原词、型号、材料、尺寸和限制条件。支持直接添加客户问题或产品变化。

验收 AC03：输入记录与去重、有效、无关、待解释、失败记录能够对账；缺失数据是 unknown，不填零、不由模型估计。

### FR04 结构化意图识别

P0。模型逐词输出对象、场景、明确条件、主要任务、客户问题、待完成判断、所需答案、证据及不确定项。关键词可对应多个候选意图，不能强制一对一。企业适配单独评估，不能把所有词解释为采购意图。

验收 AC04：结构化字段和 ID 校验通过；无关键词遗漏；明确条件与推断分开；歧义保留，不自动补造人物身份、国家、认证或采购阶段。

### FR05 候选聚类与同页审核

P0。采用原词与意图双路向量、层次候选聚类及大模型同页审核。正式问题组必须能共同支持一个主要客户任务。支持保留、拆分、合并建议及待补证据。每个成员都需进行覆盖检查，单词可成组。

验收 AC05：每组有主要任务、成员、边界和轻量答案清单；人工确认的约束生效或显式报冲突；不存在因链式相似而未经审核合并的大组；低置信项有独立状态。

### FR06 搜索结果验证

P0。对重要组、歧义词、边界词和影响新建页面的决定核对目标市场自然搜索结果。支持数据接口或人工输入，保留来源、时间、语言、地区、可用设备条件、具体结果 URL 和页面类型。

验收 AC06：缺失快照不当成零重合；冲突证据会触发意图或分组复查；模型不编造实时搜索结果。未解决关键边界不能自动触发新 URL。

### FR07 页面匹配与方向定义

P0。将问题组与现有页面逐项比对，输出更新现有页、补充模块、新建页面、观察或待补资料。候选页面方向包含对象、主要问题、判断、下一步行动、边界、类型、目标 URL、差异价值和事实缺口。

验收 AC07：任何新建建议都能解释现有页为什么无法充分承接；匹配不能只看标题；正式问题组不自动等于新增 URL。合并或删除现有 URL 仅形成建议，不自动执行。

### FR08 机会评估与任务推荐

P0。先检查业务相关性和开展条件，再评价业务价值、需求强度、竞争可行性、内容优势、当前缺口和交付成本。KD 与可用 PKD 进入竞争维度；指标保留原始来源。排序说明为什么做、现在做什么、缺什么。

必要维护单列，包括事实错误、失效产品信息和阻断询盘的问题，不以低 KD 为前提。高价值缺资料需求进入补充队列，不直接丢弃。

验收 AC08：每项建议可追溯；不简单平均组内 KD 或把搜索量求和解释为用户数；未知与低值分开；用户可调整顺序并保存原因。

### FR09 任务研究与详细大纲

P0。只为选中任务投入完整研究。分别管理企业事实与外部行业资料，输出证据、冲突和需要确认的问题。每个大纲模块包含标题、回答的问题、核心要点、来源或素材、待确认项；页面级指定内链与行动入口。

验收 AC09：问题组必答项能映射到大纲模块；不能仅交付标题列表；企业能力不能由竞争对手内容代替证明。重大缺口返回资料补充状态。

### FR10 产品页和 Blog 生成与检查

P0。两类内容使用不同结构。商业页面重点呈现适配、规格、供货或定制、证据和联系；Blog 重点呈现结论、条件、解释或比较、证据及合理产品关联。新闻包含事件日期、来源、影响对象与采购含义。

检查事实、术语和单位、站内重复任务、采购信息、标题与描述、内链和行动入口。生成式写作不允许虚构 MOQ、交期、认证、客户、案例或实测结果。

验收 AC10：关键主张有来源或企业确认；待确认内容不进入发布版；有实质答案差异而非仅同义改写；使用网站基调并允许用户修订。

### FR11 审核和增量修订

P0。展示页面方向、大纲、证据、草稿与原页面差异。允许直接修改、退回研究或请求重写，记录原因。涉及业务事实的修改写回对应事实记录，经确认后复用。

验收 AC11：审核结果绑定内容版本；批准后再次修改必须标记需复核；不会重生成并覆盖人工编辑；问题和画像调整仅影响相关任务。

### FR12 周计划与发布交付

P0。分别配置 Blog 和产品页任务。默认保留每周至少两篇 Blog 的需求，产品页更新另列；计划需要显示资料依赖、确认人、目标时间和阻塞原因。若按综合内容任务交付须明确约定。

先支持一个试点 CMS 的草稿、预览和发布；接入前可提供包含正文、元信息、素材说明、内链及目标 URL 的发布包。人工交付须回填实际 URL 和结果。授权范围内执行发布，避免重复发布并保存原版本。

验收 AC12：生成完成、已交接、已发布状态不同；失败重试不产生重复页面；修改原页面时保留恢复依据；到期缺资料时提示阻塞及可替代任务，不编内容凑数量。

### FR13 效果记录与后续建议

P0 基础记录，P1 自动同步。记录 URL、任务和版本、更新内容、时间、搜索指标及实际询盘反馈。支持按页面、问题组、查询、市场和时间查看，形成继续、完善或暂缓建议。

验收 AC13：能够对比更新前后的数据及数据缺口；点击与询盘分别统计；自动建议有依据，不承诺排名或将同期变化直接归因于内容。

## 7 意图识别与聚类实现规范

### 7.1 模型任务划分

| 模型任务 | 输入 | 输出 |
| - | - | - |
| 意图提取 | 原词、市场语言、相关术语与最小网站背景 | 候选意图、字面证据、推断字段、未知项 |
| 同页判断 | 原词和意图、轻量答案、可用搜索证据 | same_page、separate_pages 或 uncertain，以及理由 |
| 组级审核 | 组员及相邻候选组、边界与答案清单 | keep、split、merge_candidate 或 needs_evidence |

任务标签起步使用 find_supplier、customize_product、compare_options、check_spec、troubleshoot、learn_concept、other。它们用于辅助理解，不是禁止跨越的分组边界。

每个输入 ID 均须有结果。程序校验 JSON、类型、枚举、重复与遗漏；仅重试失败项。模型给出的确定程度仅用于复核触发，不作为经过校准的真实概率。

### 7.2 向量与候选聚类

为原始关键词与结构化意图分别生成向量，各自归一化后加权拼接，以余弦距离生成候选。初始等权只作为实验设置；权重由开发样本校准。企业宣传语、KD、搜索量和排序分数不进入语义向量。

首版算法路线固定为 AgglomerativeClustering，metric 为 cosine，linkage 为 average，n_clusters 为 None，distance_threshold 由标注样本确定。可用 complete linkage 做对照；不将 ward 与余弦距离组合。

原词向量单路、模型直接分组作为基线；HDBSCAN 用作可选对照，其噪声保留审阅，不按无价值删除。首版不需要训练专用 Embedding 或引入图数据库。

### 7.3 复核与约束

先为候选组生成轻量答案清单，再逐个核对主要任务是否能被覆盖；偏离词拆出，证据不足的词暂定。审核后比较邻近组是否过度拆分。代表样本只辅助发现问题，不能替代全部成员检查。

不能仅凭 A 接近 B、B 接近 C 合并全部。模型同页关系为软建议；人工确认的 must_link 与 cannot_link 为版本化约束。出现矛盾时待审。标准聚类库的 connectivity 不等于完整约束实现，首版以独立后处理层执行校验及拆合。

未解决歧义的词不充当连接其他组的桥梁，可保留多个候选关联；未确定主归属前不重复计算需求。跨产品比较与替代方案允许跨主题召回，产品类别不应形成过早的硬隔离。

### 7.4 搜索验证与增量

代表词与边界词核对具体自然结果 URL、类型和任务；缺失数据保留未知。搜索证据与模型结论冲突时回到意图或分组复核，限制自动循环次数。

新词先召回现有组的代表意图、边界成员和答案清单，再判断是否加入；无合适组则建立暂定组。对受影响组局部复核，不打乱全部已确认页面。保留组 ID、拆合谱系和发布映射。

一千词共有 499500 个全量词对，不逐对调用模型。本地向量计算承担候选发现，模型用于意图抽取、组审核和关键边界；记录成本、耗时、调用和待审数量。近邻数量、自动修订上限和预算为配置项。

## 8 核心数据对象

所有项目级对象带 project_id、稳定 ID、创建更新时间和版本。原始资料、模型推断、人工确认和发布结果分开保存。

| 对象 | 必须保留的内容 |
| - | - |
| SiteUnderstanding | 业务与产品画像、客户场景、能力边界、案例关系、内容基调、来源、缺口、版本 |
| Evidence | 原始 URL 或文件、片段位置、采集时间、事实类型、适用范围、确认状态 |
| ExistingPage | URL、页面类型、正文或快照、覆盖问题、相关产品、内链和联系入口 |
| Keyword | 原词、规范词、市场、语言、来源、指标及时间、处理状态 |
| Intent | 关键词关联、对象、条件、任务、问题、判断、答案、明确与推断字段、证据及不确定项 |
| SERPSnapshot | 查询、市场、语言、采集时间、可用设备条件、结果 URL、类型与来源 |
| ProblemGroup | 成员、主要任务、边界、轻量答案、搜索证据、约束、审核状态、拆合谱系 |
| PagePlan | 问题组关联、页面方向、类型、现有 URL 匹配、行动、独特信息、缺口 |
| OpportunityAssessment | 六个维度的等级、事实依据、未知项、优先理由、调整记录 |
| Outline | 页面方案版本、各模块的问题、要点、证据、素材及待确认项 |
| ContentTask | 类型、周计划、状态、依赖、草稿、审阅、检查与版本 |
| PublicationRecord | 目标平台、URL、内容版本、发布方式、结果、时间、重试和恢复依据 |

关系：Keyword 与 Intent 多对多；问题组聚合意图并保留关键词来源；PagePlan 可承接一个或多个相容问题组；Outline 的模块引用 Evidence。问题组主规划归属不等于搜索引擎只能展示一个 URL。效果指标关联页面与发布时间，并可回溯任务和问题组。

## 9 页面任务与大纲示例

以下为演示数据，不代表已查询真实搜索结果、搜索量或 KD。

custom silicone gasket、silicone gasket made to order、custom silicone gasket manufacturer 初步对应“寻找能够按要求制作密封垫的供应商”。how to make silicone gasket at home 对应自行制作，不能仅因词语接近混入前一组。

页面任务示例：面向有非标密封垫需求的访客，帮助判断企业能否按图纸、样品或工况要求生产，并引导提交需求。若现有定制页方向正确但信息不足，优先形成更新任务。

| 大纲模块 | 支持的客户判断 | 所需材料 |
| - | - | - |
| 可承接需求 | 我的需求是否在服务范围内 | 企业确认的产品与应用范围 |
| 材料尺寸工艺 | 能力是否满足使用条件 | 参数、工艺限制及适用说明 |
| 需求提交方式 | 没有完整图纸是否可以开始沟通 | 真实接单资料要求与可接受起点 |
| 打样与生产流程 | 合作过程如何推进 | 企业实际流程 |
| 相关样例 | 有没有类似经验 | 可披露案例或样品资料 |
| 下一步联系 | 我现在应该提供什么 | 带页面背景的询盘入口 |

若食品接触用途问题具有价值但缺少已核实的产品信息和证明，保留机会并生成补资料任务；不能因为搜索量或 KD 有吸引力就自动生成能力承诺。

## 10 机会评估规则

先做开展条件检查，输出可开展、待补资料、观察、暂缓。错误信息与询盘阻断进入必要维护队列；可选增长任务在另一队列比较机会。二者共同进入周计划，避免所有任务被流量指标支配。

| 维度 | 数据与判断 |
| - | - |
| 业务价值 | 主推业务、产品适配、销售反复遇到的问题 |
| 需求强度 | 搜索量与趋势、站点查询、客户提问；数据不足可用事实反馈但标明来源 |
| 竞争可行性 | 代表词和细分词 KD、可用 PKD、结果类型、本站现有表现 |
| 内容优势 | 真实参数、工艺经验、案例和可披露资料 |
| 当前缺口 | 现有页面无法支持的判断、已有流量与内容缺口 |
| 交付成本 | 资料、专家、制作及后续维护工作 |

V1.0 用高、中、低和证据说明，不设置未经验证的精确成功概率。先满足真实业务和资料条件，再比较业务价值及现有机会；价值接近时优先资料齐全、工作量较小的任务。允许人工调整，记录原因。

不以最大搜索量选择全部页面，不以低 KD 作为唯一标准；不简单平均组内 KD，不把多个关键词的搜索量之和解释为独立用户数。代表词及重要细分词数据分别保留。未知值不参与伪精确排序。

## 11 用户界面与状态流转

入口先提供网站地址及画像核对流程。后续界面集中于三个工作区。

| 工作区 | 核心信息和动作 |
| - | - |
| 机会清单 | 问题组、关键词、依据、缺口、排序及建议；修改分组、选择任务、补资料 |
| 页面任务 | 页面方向、证据、大纲、草稿、差异与检查；修改、退回、通过当前版本 |
| 交付记录 | 周计划、待确认、已交接、发布状态、URL 和效果；重试、登记结果、复查 |

主任务状态为候选、已选定、研究中、大纲待审、写作中、内容待审、待发布、已发布、待复查。阻塞状态为待补资料、待核对和失败可重试；另支持暂缓、取消、观察。人工发布包交出时是已交接，回填真实结果后才可标已发布。

候选选定后进入研究；关键缺口进入待补资料，补齐回到原步骤；大纲或内容不通过时回退到相应步骤。编辑已批准内容会使批准失效并返回待审。发布失败保留任务版本和目标，按幂等标识重试。发布后再次修改产生新版本和更新任务。

所有状态切换记录触发人或系统、时间、依据、输入版本与失败原因。状态不能仅根据模型声称“完成”改变。

## 12 非功能要求与实现边界

| 要求 | V1.0 规定 |
| - | - |
| 可追溯 | 来源、画像、分组、任务、大纲、草稿和发布版本可关联查询 |
| 可恢复 | 步骤可独立重试；失败不覆盖已确认结果；发布任务防重复 |
| 数据隔离 | 不同客户资料按项目隔离；未公开资料不进入其他客户生成上下文 |
| 凭据管理 | CMS 和数据服务凭据不进入提示词、正文及普通运行日志 |
| 成本控制 | 记录模型和外部数据成本；预算触达时暂停昂贵步骤并说明状态 |
| 长任务交互 | 异步执行，显示阶段与进度；支持重试与取消，不要求用户持续等待单个请求 |
| 内容访问 | 仅使用可访问内容和用户提供资料；不绕过网站权限限制 |
| 输出可靠性 | 结构化输出校验；未经核实的网页或模型内容不能作为发布指令 |
| 发布保护 | 限定目标网站及授权动作，保存修改前版本或快照；删除与 URL 合并单独处理 |

建议从 Python 单体后端、任务队列、关系数据库和原始文件存储起步。模型负责理解与组织，程序负责数字、校验、版本和状态。向量检索按试点规模采用简单实现，先不建设复杂平台。具体框架及供应商在技术设计中选择。

## 13 埋点与质量评测

最少记录 project_initialized、site_understanding_confirmed、keyword_imported、intent_generated、cluster_reviewed、opportunity_selected、outline_reviewed、content_reviewed、publication_succeeded、publication_failed 和 inquiry_recorded 等业务事件。记录项目、任务、版本、时间、结果和原因；不在分析事件中复制客户联系方式或非公开图纸内容。

模型评测使用真实关键词、业务专家与内容负责人标注的可接受分组和页面方向。歧义词允许多个合理解释或待定，不能人为强制唯一答案。同义词与近重复按组划分开发集和验证集，避免泄漏；另用不同产品类别检查迁移。

| 对照 | 评测目的 |
| - | - |
| 原词向量加聚类 | 无结构化意图的基线 |
| 大模型直接分组 | 检查漏词、顺序和跨批不一致 |
| 意图加双路向量加聚类 | 验证意图表示的作用 |
| 加同页审核与搜索验证 | 验证额外成本带来的错误减少 |

质量指标包括误合并、误拆分、漏词、重要条件丢失、词对同组 precision 和 recall、待定覆盖率、人工修改时间、页面方向接受情况。词对样本覆盖边界情况，不能只采大量容易的异组词对。轮廓系数仅用于向量几何诊断；模型自评不能替代验收。

重复运行、输入顺序变化及新增少量词时，比较成员关系和页面任务变化，不能直接比较算法数字标签。记录每个被接受页面的模型、数据和人工总成本。

## 14 发布验收与交付阶段

V1.0 的确定性验收要求：输入关键词全部有处理状态；正式问题组全部有任务、边界与成员；关键企业主张在发布版中都有可追溯依据或确认；未解决事实缺口不进入发布版；审核绑定当前版本；重试测试不产生重复页面；所有发布状态有平台结果或人工回填依据。

算法准确率、时间节省和人工修订率的数值目标在试点基线建立后确认。未达自动通过条件时保留人工复核路径，不能把全部标记待定包装成高准确率。验收同时报告已解决比例和人工负担。

| 里程碑 | 范围 | 可验收交付 |
| - | - | - |
| M1 网站理解与页面决策 | FR01 至 FR08 | 一个试点网站的画像、问题分组、页面方向和优先清单 |
| M2 内容生产 | FR09 至 FR11 | 选定产品页与 Blog 的研究、详细大纲、可发布稿与审阅记录 |
| M3 持续周交付 | FR12 至 FR13 及必要恢复能力 | 一个发布平台跑通；连续按约定节奏交付并记录表现 |
| M4 效果增强 | P1 能力 | 自动数据同步、增量发现和依据表现调整的任务 |

商业试点至少覆盖 M1 至 M3；只交付分组与大纲不能声称完成持续运营需求。试点优先比较真实性、人工投入、交付稳定性和单位成本；搜索与询盘效果持续观察，不承诺固定时间见效。

验收覆盖 AC01 至 AC13、状态回退、人工约束冲突、抓取失败、缺失搜索数据、模型输出错误及发布重试。开发周期在试点网站、人员和 CMS 确定后估算。

## 15 实施配置与待验证假设

以下事项不改变本版业务流程，需在实施或试点中确定，并记录配置版本。

| 事项 | 确定方法 | 确定前的处理 |
| - | - | - |
| 首个试点站点与 CMS | 选择有真实资料和修改权限的客户 | 先使用发布包交付，不能标记已上线 |
| 市场与语言 | 从网站读取并由用户纠正 | 歧义未消除前不执行相关市场 SERP 结论 |
| LLM 与向量模型 | 比较结构化输出、行业词理解、成本及延迟 | 保持适配接口，不承诺某型号效果 |
| 双路权重与聚类阈值 | 开发集调参，独立验证集评估 | 输出候选并审阅，不设万能阈值 |
| KD 与 SERP 数据来源 | 验证覆盖、权限、时效和成本 | 导入已有数据，缺失标记未知 |
| 自动通过条件与运行预算 | 基于错误影响、试点质量和成本设定 | 保留人工审核与预算提示 |
| 排序权重 | 先使用规则，结合真实反馈校准 | 用等级和理由解释，不输出虚假精度 |
| 质量与效率数值目标 | 测量当前手工流程并建立基线 | 报告实际结果，不写成已验证承诺 |

需要验证的核心假设：网站画像能减少业务误解；结构化意图和同页审核能减少误分组；证据约束能减少改稿；持续任务管理能让用户稳定周更。SEO 与询盘结果还受网站和市场其他因素影响，应与过程指标分开评估。
